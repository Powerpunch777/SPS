# SPS — AI 개발 작업환경

**SPS(SonParkServer)는 프로젝트 파일, 여러 AI 도구, 실행 결과를 한곳에서 관리하는 Windows 데스크톱 앱입니다.** 플러그인을 통해 게임 개발, 연구 등 프로젝트마다 다른 작업 방식을 구성할 수 있습니다.

[English](README.md) · [제품 웹사이트](https://redongames.com/sps/) · [Plugin SDK](https://github.com/Powerpunch777/sps-plugin-sdk) · [Soul Archer](https://github.com/Powerpunch777/school-arcade-unity)

**현재 상태:** 개발 중인 비공개 피드백 베타입니다. 이 저장소는 프로젝트 소개와 문서, 개발 도구를 안내하며 데스크톱 앱의 소스 코드를 포함하지 않습니다. 설치하거나 베타에 참여하지 않아도 이 페이지에서 프로젝트를 살펴볼 수 있습니다.

## 만들고 있는 이유

여러 AI 도구를 사용해 개발하다 보면 프로젝트 파일, 대화, 실행 결과, 후속 작업이 서로 흩어지기 쉽습니다. 저는 이 과정을 한곳에서 관리하고, 만들고 있는 프로젝트에 맞게 도구를 조정할 수 있는 환경을 원했습니다.

SPS는 그 환경을 직접 만들어 가는 프로젝트입니다. 프로젝트 폴더를 호스트 컴퓨터에 두고, 선택한 AI 도구를 연결하며, 실행 과정과 결과물을 기록합니다. 작업 목록, 공동 작업공간, 프로젝트 기억처럼 실제로 일하는 방식은 플러그인이 추가합니다.

## Soul Archer와의 연결

저는 이동을 멈춰야 공격할 수 있는 Unity 액션 게임 [Soul Archer](https://github.com/Powerpunch777/school-arcade-unity)를 개발하면서 SPS를 작업환경으로 사용했습니다. 게임을 만드는 과정에서 작업환경의 불편한 점과 부족한 기능을 발견했고, 이를 SPS를 개선할 구체적인 계기로 삼았습니다.

두 프로젝트는 서로 다른 관심을 보여 줍니다. Soul Archer에서는 게임 규칙이 플레이어의 판단에 미치는 영향을 탐구하고, SPS에서는 프로젝트를 만들고 수정하는 과정을 도구가 어떻게 지원할 수 있을지 탐구합니다. 필요한 환경을 정의하고 실제 프로젝트에 사용하며 개선 방향을 결정하는 것이 제가 SPS에서 하는 일의 일부입니다.

도구가 작업의 장애물이 되었을 때 문제를 살펴보고 도구 자체를 개선해 보는 과정이 이 프로젝트에서 특히 흥미로운 부분입니다.

## SPS에서 할 수 있는 일

아래 설명은 **현재 개발 후보와 선택형 확장에 포함된 기능**을 정리한 것입니다. 모든 공개 설치 파일에 같은 기능이 들어 있다는 뜻은 아닙니다. 이번에 확인한 로컬 개발 후보는 **0.4.135**입니다. 새 작업공간은 중립적인 기반에서 시작하고, 확장을 활성화하면 해당 작업 방식이 추가됩니다.

### 여러 AI 도구를 같은 프로젝트에 연결하기

SPS는 선택한 프로젝트 폴더에 AI 에이전트를 연결하고 실행 과정을 기록합니다. 에이전트는 명령줄 코딩 도구, 로컬 모델, 설정된 API 서비스를 사용할 수 있습니다. 모든 작업에 하나의 모델을 사용하도록 고정하지 않고 필요한 종류의 도움을 조합하려는 구조입니다.

Node 실행 환경에는 **Claude Code, Codex CLI, Agy CLI, Gemini CLI, OpenCode CLI, Pi CLI, Ollama, LM Studio**를 탐색하는 기능이 있습니다. 설치된 도구와 지원되는 로컬 모델 서버의 모델 이름을 확인하며, 실제 실행 가능 여부는 선택한 어댑터·계정·권한에 달려 있습니다. Codex와 Claude 실행 어댑터는 선택형 런타임 팩으로 준비하는 경로도 있습니다. 팩 자체에 AI 서비스 계정이나 구독이 포함되지는 않습니다.

예를 들어 구현에는 코딩 에이전트를 사용하고, 별도로 구성한 작업에는 로컬 모델을 연결하는 환경을 만들 수 있습니다. 어떤 도구를 제공하고 어떤 작업에 사용할지는 사용자와 선택한 작업 방식이 정합니다.

### 팀 대화를 이어가고 작업을 나누기

**SPS Team Workplane**은 지속적인 **Team Room**, 개별 과제를 위한 **Task Room**, **Lead/Worker** 작업 방식을 추가하는 선택형 확장입니다. Team Room은 프로젝트 전반의 대화를 이어가는 곳이고, Task Room은 특정 과제의 대화와 결과를 모으는 곳입니다.

설정된 Lead는 허용된 Worker에게 작업을 배정할 수 있으며, Worker의 보고를 바탕으로 후속 작업과 검토를 진행합니다. 화면에서는 작업 상태, 대화방 맥락, 첨부파일, 이미지와 텍스트 파일 미리보기를 확인할 수 있습니다. AI 제공자의 사용량 제한처럼 작업이 막힌 상황도 표시해 완료 상태와 구분합니다.

게임 개발이라면 전체 기획 대화는 한 방에서 이어가고, 전투 수정과 아트 수정은 별도의 과제로 추적하는 식으로 사용할 수 있습니다. 이는 확장의 활용 예시이며 모든 SPS 작업공간에 강제되는 조직 구조는 아닙니다.

### 진행 상황과 보고를 한곳에서 확인하기

**Dashboard**는 작업공간 상태와 활성 플러그인이 제공하는 위젯을 모아 보여 줍니다. 예를 들어 Team Workplane 위젯은 대화방과 작업, 대화방에서 확인을 기다리는 보고를 요약할 수 있습니다. **Inbox**는 플러그인 보고와 알림을 모으며 사용자별 읽음·보관 상태를 관리합니다.

이 공통 화면은 ‘무슨 일이 진행 중인지’, ‘어떤 항목을 확인해야 하는지’를 파악하는 데 쓰입니다. 보고의 의미와 제공할 행동은 각 플러그인이 정의합니다. 작업공간의 탐색 구성도 플러그인이 제공하는 형태를 선택할 수 있으며, 해당 플러그인에 문제가 생겨도 SPS의 설정·복구 기능은 접근할 수 있도록 유지합니다.

### 프로젝트에서 배운 것과 결정한 것을 기억하기

**SPS Default Memory**는 선택형 로컬 기억 기능입니다. 현재 맥락에 해당하는 승인된 정보를 찾아오는 기능과, 나중에 검토할 사실·결정·제약·선호를 기억 후보로 제안하는 기능을 구분합니다.

기억의 범위는 작업공간, 프로젝트, 에이전트, 대화방, 과제 등으로 나눌 수 있습니다. 작업 완료나 대화 요약 같은 시점에 검토 가능한 기억 후보를 만들며, 승인된 기억이나 프로젝트 파일을 임의로 덮어쓰지는 않습니다.

게임 프로젝트라면 채택한 아트 스타일이나 플레이테스트에서 발견한 제약이 기억 후보가 될 수 있습니다. 관련 프로젝트의 맥락 안에 남겨 두고 이후 작업에서 다시 찾아보는 데 활용합니다.

### 확장을 찾고 필요한 도구를 직접 만들기

**Settings > Plugins**에는 Marketplace 검색과 플러그인 상세 화면이 있습니다. 플러그인의 목적, 제작자 정보, 필요한 기능 접근 범위, 호환 조건, 변경 내용을 확인합니다. 일반 검색은 AI 없이도 사용할 수 있고, **Marketplace Assistant**는 사용자가 선택한 AI 어댑터로 대화형 검색과 비교를 돕습니다. 이 Assistant의 카탈로그 도구는 읽기 전용이므로 추천만으로 설치가 이루어지지 않습니다.

필요한 확장이 없다면 번들 **Plugin Builder**에서 제작을 진행할 수 있습니다. 별도의 플러그인 프로젝트를 수정하면서 SPS 안에 대화, 제작 단계, 빌드·테스트 근거, 패키지 참조를 모읍니다. 별도 **Plugin Preview** 창은 격리된 개발용 작업공간에서 후보 플러그인을 실행하므로 실제 작업공간을 바꾸지 않고 화면과 동작을 확인할 수 있습니다.

제작 과정은 후보 `.spsplugin` 패키지를 만들고, 호스트가 직접 신뢰하도록 선택한 폴더인 **Local Development Registry**에서 검토하는 흐름으로 이어집니다. 최종 활성화는 Settings에서 호스트가 수행합니다. Builder 자체는 설치·활성화·업데이트·삭제를 하지 않습니다. 공개 [SDK](https://github.com/Powerpunch777/sps-plugin-sdk)는 제작, 검증, 패키징, 검사, 레지스트리 도구를 제공합니다.

### 프로젝트에 필요한 전문 도구 연결하기

확장 구조는 특정 분야의 제작 도구에도 적용됩니다. 소스에는 이미지 제작 작업을 위한 **Image Worker Asset Tool** 예제 커넥터가 있습니다. PixelLab을 이용한 스프라이트, 여러 방향의 캐릭터, 애니메이션, UI, 타일셋 작업과 선택형 Meshy 3D 에셋 경로를 포함합니다.

이 커넥터는 생성 파일과 요청·작업 식별 정보를 에셋 명세에 기록합니다. 백그라운드 작업 추적으로 기존 요청을 복구해 같은 생성을 바로 다시 제출하는 일을 피하고, PixelLab 실행 전에는 예상 사용량과 구독 잔량을 확인합니다. 생성 결과는 검토할 후보이며, 검토 후 최종 게임 에셋으로 반영하는 흐름입니다.

이는 별도로 설정하는 커넥터 예시이며 모든 작업공간의 기본 기능은 아닙니다. 해당 외부 서비스의 인증 정보와 사용 가능량이 필요합니다.

### 다른 컴퓨터의 실행 환경을 연결하기

**Host** 컴퓨터는 로컬 SPS 서버를 실행하고 작업공간 데이터를 보관합니다. **Member**는 초대로 참여한 뒤 자신의 컴퓨터를 **Node**로 등록하고, 호스트 승인 후 선택한 AI 실행 도구를 제공할 수 있습니다. 컴퓨터 간 연결에는 Tailscale을 사용합니다.

프로젝트 폴더와 접근 경로는 호스트가 지정하고 승인합니다. 각 컴퓨터의 AI 서비스 인증 정보와 로컬 모델 파일은 해당 컴퓨터에 남으며, Node를 연결한다고 다른 사람에게 AI 계정 인증 정보가 복제되지는 않습니다. 다른 컴퓨터에 있는 실행 도구나 로컬 모델이 필요한 경우에 활용할 수 있습니다. 실제 두 컴퓨터에서의 인수 테스트는 출시 전 검증 항목으로 남아 있습니다.

‘로컬 중심’은 SPS 작업공간 데이터와 프로젝트 폴더를 관리하는 위치를 뜻합니다. 연결한 클라우드 AI에는 작업 중 데이터가 전달될 수 있으며, 모든 AI 도구가 오프라인으로 실행된다는 의미는 아닙니다.

### 결과를 확인하고 확장과 데이터를 관리하기

SPS는 실행 내역, 이벤트, 로그, 결과물을 기록해 어떤 작업이 이루어졌는지 확인할 수 있게 합니다. 플러그인은 패키지 검사, 호환성 확인, 작업공간별 활성화, 업데이트, 롤백 기능으로 관리합니다. 호스트에 설치된 패키지라도 특정 작업공간에서는 비활성화할 수 있으며, 플러그인 업데이트는 호스트가 명시적으로 실행합니다.

데이터 이동에는 목적이 다른 두 경로가 있습니다.

- **Workspace 패키지:** 지원되는 작업공간 기록과 설정을 내보내 별도의 새 작업공간으로 가져옵니다. 로컬 프로젝트 파일, 인증 정보, 모든 플러그인의 전용 데이터까지 포함하는 것은 아닙니다.
- **Host Transfer:** SPS가 관리하는 서버 데이터, 새 데이터베이스 백업, 존재하는 Default Memory 데이터를 내보냅니다. 복원은 새 Host 초기 설정에서만 가능하며 활성 Host를 덮어쓰지 않습니다. 외부 프로젝트 폴더는 별도로 백업하고, 복원 후 계정·폴더·Member 연결을 다시 설정해야 합니다.

진단 도구와 자동 업데이트 구조도 데스크톱 기반에 포함됩니다. 다만 구현이 존재하는 것과 새 컴퓨터 복원·서명된 정식 업데이트의 검증이 끝난 것은 구분합니다.

## 기능들이 함께 쓰이는 방식

게임 개발 환경이라면 먼저 Unity 프로젝트 폴더와 AI 코딩 도구를 연결할 수 있습니다. Team Workplane을 활성화하면 대화방과 작업 추적이 추가됩니다. Default Memory는 검토한 프로젝트 결정을 남기고, 전문 커넥터는 검수할 아트 후보를 생성하는 데 사용할 수 있습니다. 대시보드, 보고, 파일 미리보기로 진행 과정을 확인하며 다음 수정 방향을 결정합니다.

**Core**는 연결, 프로젝트 접근, 실행 기록, 저장 공간, 플러그인 관리라는 공통 기반을 제공합니다. **확장**은 실제 작업 방식을 제공합니다. 이 분리 덕분에 게임, 앱, 연구 프로젝트가 플랫폼 전체를 교체하지 않고 서로 다른 작업 구성을 사용할 수 있습니다.

## 현재 상태

SPS는 개발 중인 프로젝트이자 비공개 피드백 베타입니다. 이 소개는 **2026년 10월 10일**에 로컬 **0.4.135 개발 후보**의 제품 문서와 구현, 그보다 이전 시점의 공개 소스를 대조해 작성했습니다. 공개 소스, Preview 설치본, 정식 배포본 사이에는 기능 차이가 있을 수 있습니다.

위에 설명한 기반 기능은 개발 후보에 포함되어 있으며 Team Workplane과 Default Memory는 선택해 활성화하는 확장입니다. 이미지 제작 커넥터는 선택형 통합 예제입니다. Marketplace와 Builder의 구현은 존재하지만, 해당 출시 후보 조합에서 검색과 제작·미리보기·패키징 전 과정을 확인하는 인수 검증 근거는 추가로 필요합니다.

첫 완성형 출시 전에는 새 컴퓨터에서의 Host 복원, 실제 두 컴퓨터 간 Host/Member 테스트, Windows 코드 서명과 실제 자동 업데이트 검증이 남아 있습니다. 공개 셀프서비스 플러그인 업로드, 커뮤니티 판매·결제, macOS·Linux, 브라우저 중심 사용은 첫 출시 범위 밖입니다.

대상 환경은 Windows 10/11 x64입니다. 피드백 베타에는 승인된 계정과 지원되는 AI 실행 환경이 필요하며, 컴퓨터 간 공동 작업에는 Tailscale이 필요합니다. 설치본별 제공 상태와 안내는 [다운로드 페이지](https://redongames.com/download/)를 확인하세요.
